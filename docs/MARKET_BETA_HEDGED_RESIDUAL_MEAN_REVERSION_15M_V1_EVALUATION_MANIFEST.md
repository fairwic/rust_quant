## 3. 冻结因子与候选

每个 UTC `00:00 / 04:00 / 08:00 / 12:00 / 16:00 / 20:00`，对应 15m K 线完成后：

1. 使用币种与 BTC 此前连续 `7d = 672` 个同步 15m 对数收益；
2. `beta = cov(symbol, btc) / var(btc)`，`alpha = mean(symbol) - beta * mean(btc)`；
3. `residual = symbol_return - alpha - beta * btc_return`；
4. `residual_24h`、`residual_6h` 分别为最近 96、24 个 residual 之和；
5. `score = residual_24h / (sample_std(residual_7d) * sqrt(96))`，要求 `abs(score) >= 1.5`；
6. `residual_24h` 与 `residual_6h` 必须严格异号，证明回归已经开始；
7. 冻结 Beta 必须位于 `[0.25, 3.0]`，避免接近无对冲的单腿和不可执行的过大 BTC 名义腿；
8. 当时币池至少 80% 成员具备完整因子，否则整个时点阻塞；
9. 每个决策时点按 `abs(score)` 降序、symbol 字典序打破并列，只选一个；
10. `score > 0`：做空 1 单位币种名义、做多 `beta` 单位 BTC 名义；`score < 0` 反向；
11. 4h 节奏只为匹配预先给定的 15m `50～120 笔/月`机会密度，不在结果后调整；
12. 不使用 K 线颜色、BOS、CHoCH、FVG、影线、OI、funding、taker 或订单簿阈值。

所有因子只读取决策时点及以前的已完成 K 线；symbol 输入顺序不得影响结果。

## 4. 冻结双腿成交、风险与成本合同

- 两腿在下一根共同 15m 开盘同时入场；Beta 在整笔持仓中固定，不再平衡；
- 价差方向收益为
  `direction * (symbol_price / symbol_entry - 1 - beta * (btc_price / btc_entry - 1))`；
- 初始 `1R` 为信号时 7 日残差标准差乘 `sqrt(16) * 2`，即两倍预估 4h 残差波动；
- 初始风险必须在 `0.50%～5.00%`，否则阻塞；
- 只在两腿同一根 15m 都完成后用收盘价判断 `<= -1R` 或 `>= 2R`；触发后在下一根共同
  开盘成交，禁止用两条 K 线各自的 high/low 拼造同步价差路径；
- 最长观察 `24h = 96` 根，最后一根完成后在下一根共同开盘退出；实际开盘价差可穿越止损或目标，
  按真实开盘计算 R，不把损失或盈利截断在阈值；
- 同币最多一组；组合最多 4 组并发、同一残差方向最多 3 组；容量不足不递补；
- 每个成交腿、每次进入或退出均计 `8bps` 手续费与滑点：标准往返成本为
  `2 * 8bps * (1 + beta)`；每跨一个 UTC 8h 时点，再对两腿名义计 `1bp * (1 + beta)`
  不利资金成本；双倍成本全部翻倍；
- `1R` 固定为入场时残差风险，不因退出或随后波动回写。

## 5. 预注册停止与晋级规则

必须报告因子覆盖、Beta 门禁、候选/风险/容量/结算漏斗、交易数、有效事件、两种残差方向、月份、
币种集中度、退出原因、平均 Beta/总名义倍数，以及零/标准/双倍成本 EV、PF、胜率、trade Sharpe、
最大回撤 R 与 Recovery。

以下任一成立即永久淘汰，不扫描节奏、score、Beta、风险、目标或持仓参数：

- 零成本 EV `<=0R` 或 PF `<=1`；
- 标准成本 EV `<=0R` 或 PF `<=1`；
- 少于 300 笔或 180 个有效事件；
- 少于 8/12 个正收益月；
- 移除前三盈利币种后净 R `<=0`；
- 任一残差方向超过 80% 且另一方向不足 60 笔。

职业晋级要求标准成本同时满足净 EV `>=0.6R`、PF `>=2.2`、组合频率 `50～120` 笔/月、
Sharpe `>=1.5`，双倍成本仍为正，并且跨月、方向、币种不集中。交易级全部通过后，才以 0.5%
单笔风险、2% 最大并发初始风险计算逐时组合权益，要求最大回撤 `<=10%`、Recovery `>=4`、
日收益 Sharpe `>=1.5`。
