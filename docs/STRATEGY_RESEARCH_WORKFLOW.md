# 策略研究默认工作流（L0–L3）

> 本文规定 `rust_quant` 日常策略研究的默认执行顺序。它先解决“这个想法是否值得继续”，
> 只有通过研究闸门后，才进入完整的晋级验证。完整发布标准仍以
> [STRATEGY_ITERATION_METHODOLOGY.md](STRATEGY_ITERATION_METHODOLOGY.md) 为准。

## 1. 默认等级

| 等级 | 用途 | 默认动作 | 禁止事项 | 升级条件 |
|---|---|---|---|---|
| L0 形态分析 | 单张截图、单笔交易 | 只分析当时可见结构、提出一个可证伪假设 | 不改代码、不回填历史信号、不创建 Pine | 定义可被严格量化，且用户希望继续验证 |
| L1 快速研究 | 判断定义、覆盖率、阈值分布 | 无标签候选扫描、目标币种验证、生成候选账本 | 不跑完整组合资金路径、不看结果后改阈值、不创建 Pine | 覆盖率合理、目标样本命中、停止条件未触发 |
| L2 多币种诊断 | 判断是否值得投入完整验证 | 使用本地可用成员；缺失、退市或预热不足成员跳过并记录 | 不补造 K 线、不把部分成员结果称为正式全市场结论 | 成本后边际为正，且不是由 1～2 笔或单一事件簇贡献 |
| L3 晋级验证 | 准备合并主策略 | 完整因果回放、OOS/walk-forward、集中度、Pine/Rust parity | 不复用 L2 部分样本冒充晋级证据、不静默覆盖旧版本 | 满足项目级职业指标与版本/运行合同后显式 promote |

默认从 **L0 或 L1** 开始。只有本级结果正向，才允许进入下一等级；一个截图或一个新阈值
不再直接触发 L3。

## 2. 每轮研究的固定顺序

### 2.1 假设卡片

每轮只允许一个变量，并在查看盈亏前冻结以下内容：

```text
研究等级：L0 / L1 / L2 / L3
唯一变量：
因果定义：仅使用信号时已经完成且生产可见的数据
预计影响：预计触达基线候选的 X%～Y%
停止条件：零命中；只影响 1～2 笔；目标样本不满足；或边际成本后不为正
保持不变：币种池、窗口、成交成本、止损、目标、冲突和资金路径
```

禁止把“阈值、确认棒、止损和目标”同时改成一张卡片。无法说清唯一变量时，先回到 L0。

### 2.2 无标签可行性扫描

先只看信号时可见指标的分布、覆盖率和目标样本是否命中，不读取后续盈亏：

- 门禁一笔都碰不到：停止；
- 只影响 1～2 笔：停止，标记为样本不足；
- 用户指出的目标样本也不满足定义：停止，回到 L0 修正定义；
- 覆盖合理：进入候选账本筛选。

“无标签”指本步骤不能用退出时间、MFE、MAE、最终 R 或胜负反向选择阈值。账本可以同时保存
后续结果，但筛选器必须先只读取 `time_visible_features`。

### 2.3 生成候选交易账本

一次基线扫描固定输出：

- setup 时间（策略明确暴露时）与 signal 时间；
- 信号时可见指标；
- 信号时冻结的止损、目标与退出政策；
- 预先定义的事件簇；
- 是否成交、阻塞原因，以及后续成本前/成本后结果。

阈值先在同一账本上批量筛选。只有账本无法表达状态冲突、反手、挂单成交或资金容量变化时，
才需要重新完整回放。

### 2.4 只完整回放一个主候选

快速筛选后只选择一个主候选执行完整回放，恢复真实的：

- 下一根开盘或有限 stop-entry；
- 仓位冲突和反手；
- 冻结止损、分批退出与移动保护；
- 组合容量、相关事件与资金曲线（L3 必须）。

同一进程可以比较多个预注册阈值，但它们必须属于同一个变量，并共享同一份行情指纹和基线。

### 2.5 正向后才打开 TradingView

只有本地结果满足本级升级条件后，才抽取代表性赢家、亏家和边界样本进行图表审计。
淘汰版本不创建、不保存 Pine 脚本；TradingView 只负责可视化和 parity 证据，不反向决定历史入场。

### 2.6 批次结束统一更新文档

一轮研究只保留三份产物：

1. 一份预注册（假设卡片、数据身份、停止/升级条件）；
2. 一份机器结果（JSON/CSV，含候选账本与阶段计时）；
3. 一份结论报告（采用、保留 Research 或淘汰）。

中间阈值写入同一机器结果的 `variants`，不再各自产生独立说明文档。被淘汰阈值只在结论表中
保留一行，避免文档数量和人工图表操作随参数数目线性增长。

## 3. Rust 回测器执行合同

`tradingview_velocity_top60` 的研究加速能力遵循以下边界：

- **阶段计时**：分开记录 Pine 身份校验、数据加载、数据指纹/成员筛选、各变体回放、账本与序列化；
- **基线缓存**：只缓存所有研究维度均为 baseline 的结果；缓存键至少包含可执行文件、行情数据、
  Pine 规则、窗口、成本和币种池身份；任一指纹变化都必须 miss；
- **候选账本**：`time_visible_features` 与 `outcome` 分栏，明确 setup 缺失与阻塞事件；
- **单进程多变体**：一次加载行情，按声明顺序运行同一变量的多个注册变体；单变体输出保持原报告形状，
  多变体输出批次报告；
- **研究安全**：该入口只读 `quant_core` 本地行情，不注册 Paper/ReadOnly/Live，不写数据库，不触发交易。

L2 默认允许 `--allow-partial-diagnostic` 跳过本地缺失成员；L3 仍必须切回完整、历史成员资格正确的
严格回放合同。

### 3.1 当前 CLI 用法

首次基线会生成候选账本并写入安全缓存；同一数据和可执行文件身份再次运行时自动复用：

```bash
cargo run --release -p rust-quant-cli --bin tradingview_velocity_top60 -- \
  --rule-version candidate-v20 \
  --allow-partial-diagnostic \
  --output target/research/baseline.json
```

同一变量的已注册变体通过重复参数按声明顺序执行。当前首个接入批量协议的变量轴是
`anchor-upthrust`：

```bash
cargo run --release -p rust-quant-cli --bin tradingview_velocity_top60 -- \
  --rule-version candidate-v20 \
  --allow-partial-diagnostic \
  --anchor-upthrust-variant baseline \
  --anchor-upthrust-variant right-side-confirmation \
  --anchor-upthrust-variant target-consumption-cap-25 \
  --output target/research/anchor-upthrust-batch.json
```

单变体仍输出原有顶层报告；两个及以上变体输出
`single_process_multi_variant_batch`，其中 `variants` 保存各自完整结果，
`shared_phase_timings` 只记录一次共享加载。需要验证缓存实现本身时可显式加
`--no-baseline-cache`，日常研究不要关闭。

## 4. 每轮结束时的最小结论

结论必须同时回答：

1. 唯一变量实际影响了多少候选、成交和事件簇；
2. 成本后边际 EV/PF 是否正向；
3. 结果是否集中在少数币种、月份或事件；
4. 当前只能停在 L1/L2，还是有证据升级 L3；
5. 下一轮唯一值得验证的变量是什么，或为什么应该停止。

### 4.1 最近 10 笔亏损交易完整信号（L2/L3 必备）

凡 L2/L3 机器结果中存在完整亏损交易，结论报告必须额外列出最近 10 笔；不足 10 笔时全部列出。
统一选择与排序口径如下：

- 只选择 `complete = true` 且成本后 `net_r < 0` 的实际成交；
- 按实际 `entry_ts` 倒序，而不是按 signal 或 exit 时间；同一开仓时间按稳定 candidate ID 倒序；
- 时间必须打印 `YYYY-MM-DD HH:mm` 和明确时区，默认使用北京时间（BJT / UTC+8），不得只打印时分或 Unix 毫秒；
- 必须写明策略版本、样本组/变体和机器报告来源，避免把基线亏损与候选亏损混在一起。

每笔至少完整包含：

1. `candidate_id`、事件簇、币种、方向、交叉阶段；
2. 资格完成、突破确认、再武装、信号完成、实际开仓、实际退出时间；
3. 信号时 EMA144、EMA576、ATR14、回踩极值距离、确认收盘距离；
4. 入场价、初始止损、冻结目标、退出价和退出原因；
5. gross R、cost R、net R。

机器账本未提供的字段必须显式标记 `N/A（机器结果未提供）`，不得省略或根据后续 K 线推测。
清单后必须单列“完整账本因果复核”：至少报告完整成交/亏损总数、候选集合与风险/退出合同是否
通过复核，以及本次 10 个 ID 是否严格来自上述排序查询。不得用最近 10 笔替代全账本绩效结论。
该章节用于失败样本审计，不得反向参与同一轮阈值、入场或退出参数选择。
