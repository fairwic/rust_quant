# 严格视觉横盘突破多单确认收盘 ATR 接受余量 V7：L1 结论

## 结论

V7 **停止在 L1，不实现 Rust 交易逻辑，也不运行 L2 盈亏回测**。

本轮唯一变量为：

```text
acceptance_margin_atr
  = (确认收盘价 - 信号时冻结横盘上沿) / 突破棒冻结 source ATR
```

事前只注册 `0.05 / 0.10 / 0.15 / 0.20 ATR` 四个下限，并规定必须拒绝 V6 的 `15%～50%`
候选。实际最强的 `0.20 ATR` 只拒绝 61/421=`14.4893%`，没有任何阈值满足预注册影响门禁。
不能把 14.4893% 四舍五入为 15%，也不能在看到分布后把 0.25/0.30 ATR 临时加入同一批次。

## 四层结论

- 已知的已知：接受余量可严格因果计算，421 笔全部字段完整，但原网格影响不足。
- 已知的未知：0.30 ATR 以上的更强下限是否改善交易质量尚未研究，不能从本轮推断盈利。
- 未知的已知：P25 已达到 0.3049 ATR，说明原网格低于候选主体分布，而不是实现缺字段。
- 未知的未知：更强门禁可能删除失败突破，也可能反向删除正常浅回踩；完整冲突重排和成本结果仍未知。

## 停止边界与下一步

- 不新增 V7 enum、CLI 参数、状态事件或主策略过滤。
- 不运行 L2，不创建或修改 Pine，不接 Paper、ReadOnly、Live、数据库写入或生产。
- 本轮失败的是“0.05～0.20 ATR 网格的覆盖门禁”，不是已经证明接受余量没有交易价值。

若继续，唯一值得执行的下一动作是另开一份新预注册，仅依据本轮无标签分布研究
`0.30 / 0.40 / 0.50 ATR` 的同轴网格；仍不得读取旧窗口 outcome 选阈值，也不得同时修改确认根数、
止损或目标。
