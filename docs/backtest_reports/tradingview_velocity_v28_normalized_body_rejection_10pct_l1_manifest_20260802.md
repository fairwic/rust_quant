# TradingView Velocity V28 父横盘归一化实体否定 10% L1 预注册

## 研究等级与边界

- 当前从 L0 进入 L1；先使用 V27 既有账本的信号时字段做无标签覆盖，L1 通过后才允许实现并进入 L2。
- V28 是独立 Research-only 版本，不覆盖 V27，也不创建 Pine，不接入 Paper、ReadOnly、Live 或生产调度。
- 本文件在计算 V28 覆盖率和读取 V28 逐笔 outcome 前冻结。已知 V27 聚合结果只用于提出“原始优势不足以覆盖成本”的问题，不用于选择 V28 的逐笔样本。

## 认知框架

### 已知的已知

1. V27 要求第 1/2 根确认收盘不高于突破棒开盘，保留 V26 的 65/203 个候选。
2. V27 零成本为 `+11.298R`、每笔 `+0.174R`、PF `1.276`；成本后为 `-2.107R`、每笔 `-0.032R`、PF `0.957`。
3. V27 账本已经在信号时冻结父横盘上下沿、突破棒开盘和确认棒收盘，因此可以因果计算跨币种可比的结构深度。
4. 父横盘定义的边界触碰容差已经使用区间高度的 10%；同尺度的 10% 可以表达“确认收盘不仅刚好吞回实体，还进一步进入结构”。

### 已知的未知

1. 10% 归一化深度会保留多少 V27 候选、币种、月份和独立事件簇。
2. 该门禁是否足以让冻结成本后的平均 R 与 PF 转正。
3. 保留收益是否集中于少数币种、月份或事件。

### 未知的已知

1. L1 不需要重新回放行情：现有 65 笔账本可直接计算归一化深度，且 `outcome` 与信号字段已经分栏。
2. V28 若进入实现，只需在 V27 已通过完整实体否定后追加一个固定比例门禁，不需要改变 pending、成交、止损或退出状态机。
3. V27 三个冻结反例已经为 0；V28 必须是 V27 的严格子集，不能新增身份。

### 未知的未知

1. 更深的确认可能同时消耗目标空间、缩短止损距离并放大固定 bps 成本对应的 R，未必改善成本后结果。
2. 43/60 部分成员、统一滑点假设和相关事件仍限制结论外推。
3. 若 10% 失败，不能根据本轮盈亏继续试 5%、15% 或 20%；任何新比例都必须另开预注册版本。

## 可证伪定义

1. V27 的全部条件必须先成立，V28 不重新定义父横盘或失败确认。
2. 父横盘高度为突破时冻结的 `anchor_upper - anchor_lower`，必须大于 0。
3. 实体否定深度为 `breakout_open - confirmation_close`；V27 已保证该值不小于 0。
4. V28 唯一新增门禁为 `normalized_rejection_depth >= 0.10`，等号纳入。
5. 归一化比例在确认棒收盘时完全可见，不读取下一根成交、后续高低点、退出或盈亏。
6. 候选账本额外记录归一化比例；V27 原证据与序列化保持不变。

## L1 无标签门禁

1. 只读取 V27 账本的 `anchor.upper/lower`、`breakout_open`、`confirmation_close`、候选身份、币种、月份和预先固定事件簇。
2. 禁止读取退出时间、MFE、MAE、最终 R、胜负或 PnL 决定 10% 是否保留。
3. V28 必须保留 V27 的 20%～70%，且至少 15 个候选、8 个币、3 个月和 10 个事件簇。
4. V28 必须是 V27 的严格子集，新增身份必须为 0。
5. ALGO 2026-07-15 14:00、ICP 2026-06-29 09:00 和 SHIB 指定反例继续为 0（Asia/Shanghai）。

## L2 停止与升级条件

1. L1 通过后才增加 V28 独立枚举、稳定 CLI 名称、账本证据和边界测试。
2. 只使用本地已有且预热完整成员，不同步或补造 K 线。
3. 在同一进程、同一数据指纹中并排回放 V27/V28，恢复相同的下一根开盘、冲突、止损、目标和退出。
4. 成本继续固定为每边 `5 bps` 手续费和 `3 bps` 滑点。
5. V28 成本后平均 R 必须大于 0、PF 必须大于 1，且正收益不能只来自 1～2 笔或单一事件簇；任一不满足即停止在 L2。
