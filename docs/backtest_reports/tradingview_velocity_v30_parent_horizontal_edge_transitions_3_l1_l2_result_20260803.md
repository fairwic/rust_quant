# TradingView Velocity V30 父横盘三次边界交替 L1/L2 结论

## 结论

V30 的形态定义能删除截图中“先筑底、后单向修复”的伪横盘，但历史回放证明它不是有效的盈利过滤器。本轮停在 L2：保留独立 Research-only 代码和证据，不创建 Pine，不接入 Paper、ReadOnly、Live 或生产策略。

V30 从 V29 出发，只增加一个信号时可见门禁：V29 已经选定的最长父横盘，在突破棒之前必须至少完成三次上下边界交替。父横盘、P90/P10 边界、方向效率、浅突破 10%、放量、首次突破、第 1～2 根完整实体否定、成交、止损、目标、冲突和退出均保持不变。

在相同 43/60 本地成员中，V30 从 V29 的 27 笔保留 20 笔，覆盖 18 个币、9 个月和 20 个 60 分钟事件簇，L1 覆盖通过。但 V30 成本后为 `-2.155R`、平均 `-0.108R/笔`、PF `0.865`，明显差于 V29 的 `+5.128R`、`+0.190R/笔`、PF `1.277`，触发预注册停止条件。

## 四层判断

### 已知的已知

- V30 是 V29 的严格子集，代码没有制造新增身份或改变保留交易的风险/结果。
- 形态过滤覆盖足够广，不是只影响 1～2 笔的偶然规则。
- 成本后 EV/PF 均转负，且删除队列显著盈利，不能进入 L3。

### 已知的未知

- 边界交替是否更适合作为纯视觉标签，而不是交易门禁，尚未在独立指标任务中验证。
- 20% 边界带的邻域没有搜索；本轮结果失败后禁止继续用同一历史尝试 10%/15%/25%。

### 未知的已知

- 原 `Consolidation Zones - Live` 把极值不更新当横盘，确实会误画方向修复；这个视觉问题真实存在。
- 交易策略需要的是可交易供给边界，不必等价于教科书式多次往返横盘；把视觉标准直接变成开仓门禁是本轮失败的核心原因。

### 未知的未知

- 2026-08-03 之后的新冻结窗口、真实点差和资金费可能改变 V29/V30 的边际，但当前没有独立 forward OOS 证据。
- 当前 universe 只有 43/60 本地完整成员，并带 current-live 幸存者偏差，不能外推为全市场结论。

## 最终决定

- L0 因果定义：通过。
- L1 无标签覆盖与严格子集：通过。
- L2 成本后绩效：失败。
- L3：未开始。
- Pine：未创建。
- V30：仅保留 Research-only 证据，不 promote，不接 Paper/ReadOnly/Live。

最值得执行的下一步不是继续调交替次数，而是把“视觉横盘指标”和“交易锚点选择器”拆成两个独立目标：视觉指标可以拒绝方向修复，但交易策略暂时保留 V29，不把该视觉门禁接入开仓。
